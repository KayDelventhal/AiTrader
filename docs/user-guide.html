01 / GET STARTED

Start, sign in and stop the app

Open PowerShell in the AiTrader repository and run the existing virtual environment’s Python. The start command applies database migrations, creates missing initial records, and serves the built application on your computer:

.\.venv\Scripts\python.exe scripts\manage.py start

Visit http://127.0.0.1:8000. Select a Demo account, check the Password, then select Open demo workspace. The standard owner account is Alex Morgan (owner, password local-demo-owner); the partner is Sam Taylor (partner, password local-demo-partner). A password configured during initial setup may replace the standard value.

The owner can manage the shared collection configuration and operating costs. The partner can read those shared records. Accounts, proposals, personal watchlists, annotations and job access retain their own user boundaries. This preview is intended for the local computer, with intentionally known demo credentials.

To stop the managed server and its workers, run:

.\.venv\Scripts\python.exe scripts\manage.py stop

Closing a browser tab, signing out or closing the terminal that launched the server does not stop the managed process. The stop command checks its saved process identity before stopping it. Saved database records remain available the next time you start. The app cannot collect feeds while the server or computer is stopped.

03 / OVERVIEW

Read the workspace at a glance

Overview summarizes the fictional trading workspace. Paper cash is the local demo account’s spendable cash. On your watchlist counts watched fictional instruments. Strategy versions counts saved strategy records, not running trading systems. Awaiting your review counts local proposals that still have a valid approval window.

Open terminal and Full terminal lead to the detailed chart area. The instrument buttons above the market chart switch the selected fictional instrument. The shown change is based on the fixture’s last bars; it is not a live market movement.

On the radar contains the original synthetic event examples. Select a card or Explore all research to open Research & events. Genuine collected publications appear in its separate Source library tab. Manage beside the watchlist opens Terminal; selecting a watchlist row opens that instrument. Open strategy lab opens the strategy notebook. View setup opens Settings & status.

04 / TERMINAL

Explore charts, indicators and replay

The Terminal combines an instrument list, a daily candlestick chart and fixture research context. Select an instrument to load its chart. Watchlist stars add or remove the instrument from your personal watchlist; they do not create a trade. Wider layouts have draggable panel dividers for adjusting space.

Add a currently supported instrument: open Terminal, find it in the Instruments panel and select its star. The current catalogue contains fictional instruments only; Search instruments filters that existing catalogue and cannot add a new real ticker such as NVDA or AMZN. Removing a star deletes only the personal watchlist association, not the instrument, price bars, saved strategies, jobs or research documents. A persistent Focus / On hold lifecycle and watchlist-change history are planned but not available yet.

A candle represents one fictional daily bar. The displayed O, H, L, C, V values mean open, high, low, close and volume for the latest visible bar. Use the chart’s crosshair, mouse wheel and dragging to inspect and navigate its time and price axes. The current interval is 1D; selecting another holding horizon elsewhere does not create hourly or intraday bars.

Advanced trend lines, Fibonacci tools, position drawings, live order books and automatic chart annotation are not implemented in this version.

05 / STRATEGY LAB

Save an idea and test a specific version

The strategy notebook currently implements a long-only moving-average crossover strategy. It enters when the fast SMA crosses above the slow SMA and exits on the reverse crossover. The backtest executes signals at the next bar’s open and includes the selected fees and slippage. The numerical engine is vectorbt; the dataset is still fictional.

Several notebook records can therefore be variants of the same algorithm. Changing only the name, hypothesis or planning horizon does not produce a different signal rule. There is no strategy-family selector, natural-language strategy compiler or news-conditioned backtest in this version.

Field or buttonMeaning
Notebook versionLoads that saved version into the form and selects it as the workbench’s backtest subject. Editing the form does not alter the saved version.
New strategyStarts a new draft with a new name and hypothesis. Its horizon starts with Use workspace default when saving. Check the other inherited form values before saving.
Strategy name / HypothesisRecord the idea and the mechanism you want to test. State what would disprove it; this text alone does not define additional trading logic.
InstrumentChooses a currently supported fictional instrument. A real company research domain is a different object.
Strategy horizonRecords intraday, days to weeks, weeks to months, or the workspace default resolved when saving. It describes intended holding time; the current engine still uses daily fixture bars.
Fast SMA / Slow SMASet the averaging periods. The fast period must be smaller than the slow period.
Whole sharesSets the strategy’s whole-share trade size.
Fees / SlippageSpecify basis points; 100 basis points equal 1%. These costs affect the backtest’s hypothetical execution.
Save strategy draft / Save new versionPersists an immutable version. Saving your existing strategy creates another version; it does not rewrite previous results or activate automatic trading.
Run backtestQueues the selected saved version, not unsaved form edits. Exact inputs are captured before the background calculation starts.
Export result and assumptionsDownloads the selected result as JSON, including its reported assumptions. It does not execute an order.

The workbench shows total return, maximum drawdown, closed trades and win rate. An undefined win rate is a meaningful result when no qualifying closed trades exist. The equity curve shows hypothetical capital through time. The execution journal lists fill and signal dates, side, shares, price and fees. Read the higher-cost sensitivity and assumptions alongside the headline return.

Saved runs

The current notebook saves versions and runs manual backtests. Strategy activation/deactivation and multiple algorithm families are not implemented yet. The planned library will let you configure a strategy, save and compare immutable versions, test them, and explicitly activate or deactivate a selected version for monitoring or a configured local simulation. Editing an active version will create a new version. Deactivation will preserve history and will not silently close existing positions; broker execution remains a separate capability.

Inspect a saved run changes the displayed completed or pending job. Selected result identifies its subject and version, which can differ from the form currently open. The holding horizon and attributed expenses remain attached to that run. “No expenses attributed” means no costs were assigned to that job; shared research may still have costs in Settings.

Frozen inputs means the app saved the submitted data and an integrity digest. Export inputs downloads that snapshot. Legacy run marks an older run for which those inputs were never captured; the app does not invent them retrospectively. History currently covers the latest 50 jobs across the signed-in user’s backtest and fixture-research jobs.

07 / DATA GATHERING

Configure several domains and start collection

Open Research & events → Gathering setup, or use Settings & status → Research gathering → Configure gathering. A domain is a durable research interest: a company, sector, commodity, country, macroeconomic theme or geopolitical issue. The initial interests are NVIDIA, Amazon, macroeconomics and geopolitics. You can add others without creating another database.

Research domains

Select Add domain or an existing card’s Edit domain. Enter a Domain name, a Domain description, and optional Keywords and related entities, separated by commas. Active research interest marks whether that topic is currently active. Select Save research domain to persist it, or Cancel to discard the form.

Examples of useful keywords include a company’s name, ticker, important supplier, sector and known exposure such as chips, cloud, energy, export restrictions or interest rates. These are stored research metadata in this version. They are not a functioning semantic classifier or a filter that rejects every article lacking the words. Changing a domain does not rewrite its older recorded snapshots. New feed runs exclude inactive domain assignments; when all assigned domains are inactive, that source pauses until at least one becomes active again. Manual historical imports can still be assigned to an inactive domain.

A new domain does not automatically gather new material. After saving it, use Add source or Edit source to assign a relevant catalogue feed and enable that source. Creating a company domain neither adds a trading instrument nor discovers an appropriate publisher. Automatic instrument-to-domain linking and suggested related topics remain planned. Deactivating a domain preserves its existing documents and recorded associations.

How gathering differs from search

The current collector periodically downloads the latest items from enabled, fixed RSS/Atom feed addresses. It stores the returned titles, excerpts and links within its size/item limits; it does not run company-keyword queries against the web, search every article page or use an LLM. Configure sources, assigned domains and Check every (minutes) here. Keywords and related entities describe your interests but do not change what a feed publishes. Search stored sources in the Source library only searches text already saved in this database.

Adding a topic without a suitable source leaves a coverage gap. The available catalogue is limited; assigning an unrelated feed to a domain does not make it comprehensive coverage. Company evidence, sector/dependency evidence and broad macroeconomic/geopolitical evidence are intended to work together in future adaptive research. Changing watchlist stars does not currently change gathering.

Collection sources

Select Add source, choose from the Public feed catalog, select one or more Domains this source may inform, choose Check every (minutes), and decide whether to Enable this source for collection. Select Save collection source. The allowed interval is 15 to 10,080 minutes; 60 minutes is a practical initial setting for these publishers. Edit source changes its assignments, interval or enabled state.

A single source can inform several domains and is downloaded once for that configured source. Broad monetary-policy or geopolitical feeds can be assigned alongside company domains even when the company is not named. The assignments mean “configured coverage,” not “every article affects every selected company.” The present collector retains the feed material for later review; it does not yet assign an LLM relevance score or causal claim.

Catalog sourceWhat it covers

AWS news blogAmazon Web Services cloud and product announcements. It is useful Amazon-related context, but does not cover all Amazon retail, earnings, workforce or regulatory developments.

The current catalog contains reviewed public RSS endpoints. The UI does not accept arbitrary feed URLs, scrape article pages or purchase news subscriptions. Some feeds provide a useful excerpt; others provide mainly a headline and link. The original publication remains accessible from the stored record. Respect publisher attribution and the source’s usage terms when using or sharing material.

Start, pause and inspect gathering

  1. Save at least one source with its own collection checkbox enabled and at least one active assigned domain.
  2. Select the workspace-level Enable collection button. The banner changes to Collection enabled when the runtime also permits public requests.
  3. Use a source’s Collect now to queue a check, or let its scheduled check become due.
  4. Read the Collection run log, then switch to Source library to inspect stored records.

Pause collection stops new workspace collection requests. Disabling an individual source pauses only that source. Existing documents remain stored, and a request already in flight may still complete. The application and computer must remain running for scheduled collection. It does not create an operating-system task or a cloud service.

Each source shows its Check interval, Last checked, Last success, Next due and latest error. Last checked means an attempt began; it does not prove a successful retrieval. A success can legitimately add zero new records because all supplied content was already stored.

The run log distinguishes manual requests and scheduled checks. QUEUED is waiting, RUNNING is fetching, SUCCEEDED means the retrieval and storage step completed, FAILED records a failed or interrupted attempt, and CANCELLED means a queued request was not allowed to start. Counts distinguish received items, new documents, new revisions and unchanged records. A failed source is not replaced with demo material.

Select a Revision history entry to inspect an earlier saved version. Export source history downloads the document and the revisions visible under the current knowledge cutoff as JSON. Open original publication opens the publisher’s URL in a separate browser tab. The remote page may have changed since collection; the stored excerpt records what the app retained at its observation time.

Import historical material

Select Import historical source. Supply the Publisher, an HTTPS Publication URL, a Publication title and the Source text or excerpt you want to retain. Choose the relevant domains. Choose Publication date precision: Unknown, Date only or Exact date and time. Date only asks for a Publication date only value; Exact date and time asks for Published at (UTC). Do not invent a time when the publisher supplies only a date. Optionally add Event occurred at (UTC) and an Import note explaining provenance, corrections or uncertainty. Select Import source to save it; Cancel closes the form without saving.

The form accepts up to 50,000 characters of source text. It does not fetch the entered URL or certify that your text is authentic. Keep sufficient original context and a traceable source reference. Reimporting changed material under the same manual publication identity creates a new revision; previous content is retained. The application uses request identifiers to avoid storing the same submitted operation twice after a repeated response.

Example: old publication, newly acquired knowledge.

Suppose you import an article published on 15 March 2020 on 27 October 2026. It belongs in a publication timeline for March 2020, but a “Known by this app” cutoff in 2020 must exclude it. The app did not possess that record then. An archived historical dataset needs its own evidence of which version was available at the historical time.

Public RSS feeds usually expose a limited recent window. Collecting them now starts a durable local history and may bring in some older items still present in the feed; it does not reconstruct every event from previous years. Historical source imports provide an initial backfill path. Large archive connectors, automated event extraction, semantic deduplication across publishers and verified historical availability are separate future work.

09 / LOCAL SIMULATION

Portfolio, proposals and explicit approval

This area is a fictional local account starting with EUR 10,000. Available cash is not borrowed money. Position value uses frozen fixture prices. Realized P&L includes booked execution fees. The standard order controls limit an order to EUR 500 including fees and a position to EUR 1,000.

To exercise the workflow, choose Instrument, Side (BUY or SELL) and Whole shares, then select Create proposal. The app validates cash, holdings and limits, stores the proposed payload, and opens the review dialog. It does not fill the order merely because you created it.

The review shows the exact quantity, fill price, fee, total debit or credit, reference fixture date, expiry and order fingerprint. The simulated fill assumption is a fixture snapshot with slippage, not a real broker or next-open market execution. Select Approve local fill to book that exact proposal once, or Reject to reject it. Closing the dialog leaves the proposal awaiting approval until it expires or is otherwise resolved. Review proposal reopens an eligible pending proposal.

Approval normally expires after 120 seconds and is tied to the account state. If another fill or account control changed that state, create and review a new proposal. Repeating approval for an already completed proposal does not book another fill.

Pause local execution activates the kill switch and blocks new fills; it does not sell your positions. Resume local execution allows new proposals after review. The Positions table, Proposals & fills list and Audit trail show recorded changes. Export journal downloads the account, proposals and visible audit records with their LOCAL_DEMO environment label.

10 / SETTINGS & STATUS

Choose defaults and inspect capabilities

Markets to observe contains United States and Europe. These are persisted planning choices, not proof that real quote providers are connected. At least one market must remain selected. Default research horizon starts at Days to weeks; you can select another supported holding horizon for future work. A saved strategy or completed run keeps its original horizon.

Monthly operating limit (EUR) starts at EUR 20 and is shared across AI, search/news and market-data expenses. Select Save workspace defaults to apply an explicit change. The revision badge identifies the current saved configuration. If another editor changed it first, refresh and review the new values instead of silently overwriting them. The partner sees these settings read-only.

Research gathering → Configure gathering leads to the actual domain/source controls. A Pending or Not implemented label is deliberate: the UI must not substitute a fabricated success for a missing capability.

11 / OPERATING COSTS

Track actual bills and protect the budget

The operating-cost dashboard lives in Settings & status. Select a Budget month to inspect that Europe/Berlin calendar month. Export cost ledger downloads totals, records, revision history and pricing/FX references. The budget changes only through an explicit owner save; positive demo performance never increases it.

AmountWhat it means

Estimated expensesIncurred usage for which a usable estimate exists, awaiting final billing.
Reserved this monthCommitted allowance for work or monthly charges that have not yet been booked as an incurred expense.

Record an expense

Select Record expense. Enter Provider, Cost category, Expense description and Cost certainty. Categories are AI analysis, Search & news and Market data. Choose Confirmed amount, Estimated amount or Unknown or uncertain charge. Known amounts need the Original amount and three-letter Billing currency.

For a non-EUR bill, enter EUR per 1 [currency] and the FX reference time (UTC). For example, a USD bill converted at 0.90 EUR per USD uses 0.90, not its inverse. Keep a Pricing or invoice reference that explains the rate or invoice basis. The backend uses Decimal accounting and stores micro-EUR amounts; UI formatting is not the accounting engine.

Assign cost to leaves the charge shared or assigns it to one saved analysis/backtest or one owned strategy version. Attribution records the charge once. It does not copy the full expense across every instrument or prove that a particular analysis generated a profit. Select Record expense to save it; Cancel discards the form. Recording a bill does not contact or pay a provider.

Correct a record and inspect history

Each ledger row offers History and, for the owner, Update. History shows revision, actor, time, reason, recorded expense, original billing amount and conversion basis. Update lets you reconcile an estimate or unknown amount with the bill. Enter a Reason for update and select Save cost update. Earlier records remain available.

An eligible uncharged reservation can be marked Cancelled — no charge. A manual bill that was entered incorrectly can be corrected to a confirmed amount of zero with an explanation. The app records real late bills even when they exceed the ceiling; it blocks new paid admission rather than hiding an incurred expense.

Monthly commitments

Add monthly commitment records an existing or planned recurring accounting obligation: Commitment provider, category, description and Monthly commitment (EUR). Save monthly commitment reserves its amount once per applicable month. It does not buy a subscription. Reconcile each generated monthly cost when the actual bill is known.

Stop future entries prevents future local monthly commitments and keeps the current and historical entries. It does not cancel the external provider subscription. Recurring entries materialize when the app performs a relevant cost/report operation; this is accounting behavior, not proof that an external invoice was received.

Trading results & operating expenses

This panel separates realized demo P&L, unrealized fixture valuation and an illustrative result after expenses. The illustration subtracts all shared confirmed and estimated monthly operating expenses from the current account’s realized demo P&L. Reserved amounts are shown separately, and fees already booked in trading P&L are not deducted twice. Unknown costs or an account that cannot be reconstructed from saved fills make the complete net result unavailable.

The cost ledger can contain real bills even though the trading profits are fictional. Demo gains cannot fund those bills. Automatic provider billing import and actual paid LLM usage collection remain pending; expenses elsewhere in the same provider account are not automatically visible here. Public-feed gathering in this milestone makes no paid model calls.

12 / YOUR DATA

What is stored, and where

The default local database is .runtime/aitrader.db. SQLite may also create its normal write-ahead-log sidecar files while the app runs. The database retains users and password hashes, sessions, personal watchlists, fictional instrument bars, fixture events, strategy versions, job inputs/results, accounts, proposals/fills, annotations, notices and audit records.

It also retains workspace setting revisions, budget months, cost records/corrections and recurring commitments. Gathering adds domains, source configuration, collection run snapshots/results, source-document identities, immutable content revisions and historical import records. A later source correction adds a revision rather than quietly replacing the earlier stored content. Duplicate detection is scoped to a source/publication identity; the app does not yet equate every syndicated article across different publishers.

.env stays on the server side and may hold credentials or runtime preferences. It is not the place to configure each research domain; use Gathering setup. The source collector uses reviewed public URLs without API keys. Python dependencies are in .venv/. Local tooling is in .tools/. Logs are in .runtime/server.stdout.log and .runtime/server.stderr.log. Browser tests use separate databases under .runtime/e2e/; screenshots and other local validation outputs are in artifacts/.

Exports are useful, but not complete backups

Individual JSON downloads preserve a selected run, input snapshot, source history, cost report or account journal. A whole-database backup preserves the connected workspace state. Use the supplied SQLite online backup command so a consistent snapshot is taken even while the app is running. Choose a new destination name:

.\.venv\Scripts\python.exe scripts\manage.py backup .runtime\my-backup.db
.\.venv\Scripts\python.exe scripts\manage.py restore .runtime\my-backup.db .runtime\restored-copy.db
.\.venv\Scripts\python.exe scripts\verify_persistence.py .runtime\my-backup.db .runtime\restored-copy.db

Restore always writes to a new destination; it does not overwrite or automatically switch the running database. Verification compares application table schemas and rows and checks SQLite integrity and foreign keys. Backups contain private source text, password hashes and session records. Store them accordingly. A database backup does not separately back up your .env, application source or downloaded HTML guide.

13 / BACKGROUND WORK

What runs when you are not looking

The current application is a single local server process with separate bounded workers for numerical/research jobs and public-feed collection. You do not need Docker, Redis, Celery or a cloud account to use it. The browser is a view into that process; it is not the scheduler.

ActivityBehavior
Backtest / fixture researchQueued through the app, calculated in the local worker, saved in SQLite. Interrupted running jobs are marked failed after restart rather than claimed complete. Pending jobs can resume.
Public-feed schedulerChecks enabled sources for due work while the process is running. Each source is fetched one at a time. Missed intervals are coalesced into a current check instead of replaying every missed hourly request.
Collection requestUses a fixed catalog endpoint, timeout, download-size and item limits. It does not follow redirects, fetch every article link or pass source text to an LLM.
Source revisionsUnchanged material is counted without a duplicate revision. Changed content or recorded attribution is retained as a new version with its actual observation time.
Interrupted feed runMarked failed during recovery. A subsequent scheduled or manual check can read the current feed; persistent identity checks prevent it from duplicating unchanged documents.
View refreshesThe UI refreshes active jobs and collection views periodically. Browser polling is not proof that a new external request was made.

The collector takes at most 100 feed entries from a bounded 2 MiB response and rejects unsafe or unsupported XML. This limit is another reason that a successful collection is not a complete archive. It records summaries provided by the feed and does not import full article bodies through linked-page scraping.

A runtime-level public-network disable switch can prevent all feed requests even if saved source settings are enabled. Tests use this boundary to keep real network calls out of isolated validation. For ordinary use, the app’s workspace toggle and each source’s checkbox still need to permit collection. Running multiple independent application processes is not a supported distributed deployment.

14 / CURRENT BOUNDARIES

What is real now, and what is still planned

Working locally

Public feed retrieval when enabled; editable research domains and source assignments; a persistent source library with revisions and manual historical imports; numerical indicator/backtest calculations on fixture prices; frozen run inputs; a precise fictional ledger; manual operating-cost accounting; local help and exports.

Not connected yet

Real US/European stock-price feeds, real trading instruments and broker execution; paid news/search adapters; LLM analysis and automatic model billing; semantic event extraction and full longitudinal reasoning; advanced chart drawings and fully isolated historical training.

The next AI workflow is intended to use cheaper models for curation and premium models for development analysis, portfolio relevance and critical review, with selectable model settings, bounded rounds and recorded cost. These planned controls are not hidden in an existing tab: they have not yet been implemented. Supplying an OpenAI key or collecting a feed will not activate them automatically.

The intended review cycle is source-linked analysis, critique and a bounded revision, retaining unresolved disagreement. Model-specific temperature and reasoning options will be validated; unsupported settings will not be presented as effective. A future system must also distinguish a model’s prior knowledge from the evidence available at a historical cutoff. Modern-model retrospective exercises cannot automatically be treated as blind historical tests.

Risk monitoring and trigger moments: planned

There is no real grey-rhino detector or configurable risk-trigger rule in this version. Demo event cards are synthetic examples. Manual and Scheduled in the collection log explain why a feed was fetched; they are not market-risk triggers.

The planned design retains a risk hypothesis over time, including evidence, exposed companies or sectors, alternative explanations, uncertainty, a review horizon and explicit escalation/invalidation conditions. A trigger would record a material change or a versioned threshold crossing, with the previous assessment retained. It would request review, not automatically place a trade. More copies of the same story would not count as independent confirmation.

Planned agent structure and shared memory

Collect → Curate → Connect developments → Assess portfolio relevance → Challenge conclusions → Publish a research assessment

RoleResponsibility
Collector and coordinatorRetrieve permitted material, schedule bounded work and enforce the shared budget. Ordinary code performs retrieval; collection itself is not an LLM conclusion.
Curation agentUse a cheaper model to decide Keep, Review or Discard based on evidence quality, novelty and direct or indirect relevance. Keep useful evidence; bound the uncertain review queue; retain only compact, time-limited rejection metadata. A missing company name is not sufficient reason to discard an early signal.
Development analystConnect new observations with older evidence across domains. Preserve the evidence, uncertain assumptions, counterarguments and expected delay at each connection. Update hypotheses instead of forgetting earlier findings.
Portfolio relevance agentCheck those chains against dated holdings, Focus / On hold interests, known exposures and horizons. Distinguish real holdings from demo positions and unknown exposure from no exposure.
Critical reviewerChallenge both the chain and its portfolio interpretation, request bounded follow-up, and retain disagreement. Agreement between agents is not independent factual proof.

All roles use shared, versioned evidence and assessment history. Domain-specific work can share models and processes; it does not require a separate always-running program for every domain. A hypothetical worker shortage might delay generator deliveries and later affect data-centre commissioning, but every link needs evidence and alternatives such as inventory or substitutes must be checked. The system should distinguish a plausible economic effect from an established trading advantage.

Current collection still stores valid bounded feed items without this model-based quality selection. Keep / Review / Discard controls, selective-retention settings and the agent roles above are planned; this documentation update does not remove existing source records.

Planned impact flags and strategy use

AssessmentDisplay and interpretation
Negative impactRed flag for a material adverse or downward effect, with an affected instrument, explanation and time horizon.
Positive impactGreen flag for a material favorable or upward effect, with an affected instrument, explanation and time horizon.
Assessed no material impactNo flag. The assessment remains in history.

Flags will link to their evidence, counterarguments, uncertainty, critic outcome and review/expiry conditions. Conflicting supported drivers remain visible instead of cancelling each other silently. Text labels accompany color. These flags do not exist in the current app.

Strategies will display relevant research in Advisory mode by default. Explicit, saved rules may later use flags as filters or entry/risk conditions. An agent will not silently rewrite, activate or deactivate a strategy. Flag color describes the expected effect on the instrument; whether that effect helps a particular strategy is evaluated separately. A negative instrument outlook could support a future short strategy, whereas the current backtest is long-only. Tests must retain the exact strategy and evidence versions available at the simulated time.

15 / TROUBLESHOOTING

When something looks unexpected

I cannot find where to configure news gathering.

Open Research & events, then Gathering setup. Settings & status also has Research gathering → Configure gathering. Domains and source schedules live there; the terminal watchlist controls fictional instruments and is a separate feature.

I added a company domain but cannot see its stock chart or new company news.

Domains are research topics, separate from the fictional instrument catalogue. Adding a domain does not connect real prices or invent a news source. Assign a relevant supported feed under Gathering setup; if the catalogue lacks one, that coverage is still missing. Watchlist-driven domain creation and broader search are not implemented yet.

How do I put a stock on hold?

That state is planned, not an existing button. The current star removes only watchlist membership and preserves the underlying instrument and research, but does not preserve a focus-state history. For research topics, Edit domain lets you turn off Active research interest without deleting stored documents; this is a separate collection control.

Collect now is disabled.

Check that you are signed in as the owner, workspace collection is enabled, the source itself is enabled, at least one assigned domain is active, the runtime allows public requests, and no run is already active for that source. A source whose assigned domains are all inactive is paused for new collection.

The source says SUCCEEDED but no new documents appeared.

Read the run counts. The feed may contain only previously stored material. Clear library filters, including Known by this app, and check the chosen domain/source. Feed windows are limited; collection success does not mean that new events occurred.

A publisher is unreachable, moved or returned invalid content.

The run remains failed with a visible error and no substitute records. Check again later if it was a transient outage. A changed endpoint needs review in the supported catalog; the collector will not follow an arbitrary redirect automatically.

An old article disappears when I choose an old knowledge cutoff.

Its publication date may be old, but the app first acquired it later. The cutoff deliberately excludes information the app did not possess at that time. Remove the knowledge cutoff to inspect the backfill.

A publication date says Not recorded.

The source may omit a date or supply one without a usable timezone. The app preserves uncertainty rather than guessing. Use the source link and retained metadata to investigate; first-seen time remains a different fact.

I changed a strategy form but the result stayed the same.

Results belong to saved versions. Save the new version, confirm the selected workbench subject, and run it. The Saved runs selector can still point to an earlier result, whose label and input hash identify it.

A local proposal expired or reports Account changed.

Its short approval window or saved account revision is no longer valid. Create a fresh proposal and review its current exact payload. Reusing the old approval is deliberately rejected.

The budget is blocked although the confirmed total is below EUR 20.

Estimated expenses, current commitments, unresolved earlier-month holds or unknown charges can consume the allowance. Inspect the other totals and record history. Resolve uncertain billing using its evidence; do not assume it was free.

The interface still looks like an older version.

Refresh the browser after the latest production build. If backend behavior changed, stop and start the managed server. Preserve the existing database and configuration; reinstalling or deleting them is not the first troubleshooting step.

The app is unavailable after I close everything.

Confirm the managed server is running with the start command in section 1. The server must run for local collection; a powered-off computer cannot gather updates. Read the server logs if startup fails, and retain the error message for diagnosis.
